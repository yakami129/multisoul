# SPEC: iOS App 国际化（i18n）— 英文 + 简体中文

**日期**: 2026-06-08  
**状态**: 待实施  
**模块**: mobile/

---

## 1. 背景与目标

MultiSoul iOS 界面目前全部为英文硬编码字符串。本 SPEC 为应用添加国际化支持，首期支持**英文（en）**和**简体中文（zh）**，用户可在设置页面随时切换，立即生效。

**目标**
- 所有静态 UI 文字支持英文 / 简体中文双语
- 切换语言无需重启 app，立即生效
- 首次启动跟随设备语言（中文设备默认简体中文，其他默认英文）
- 语言偏好持久化，重启后保持上次选择

**非目标**
- 不翻译服务端返回的动态内容（agent 名称、对话消息、spec 内容等）
- 不支持 RTL 语言
- 不支持繁体中文（本期）
- 不支持机器翻译 / 自动检测 UI 文字

## 3. 技术方案

### 3.1 依赖

```
i18next
react-i18next
expo-localization        # 检测设备语言
@react-native-async-storage/async-storage  # 已有依赖，用于持久化
```

### 3.2 文件结构

```
mobile/src/i18n/
├── index.ts             # i18next 初始化，导出 useTranslation hook 及类型
└── locales/
    ├── en.json          # 英文翻译
    └── zh.json          # 简体中文翻译
```

### 3.3 i18next 初始化（mobile/src/i18n/index.ts）

- 使用 `expo-localization` 获取设备语言
- 优先读取持久化的用户选择（`languageStore`）；无选择时回落设备语言
- 语言回落链：`zh → en`（所有未翻译 key 显示英文）
- 支持 `{{ variable }}` 插值（如 `{{count}} machines`）

### 3.4 状态管理（languageStore）

新增 `mobile/src/store/languageStore.ts`：

```ts
interface LanguageStore {
  language: 'en' | 'zh';  // 用户显式选择的语言
  setLanguage: (lang: 'en' | 'zh') => Promise<void>;
}
```

- 持久化键：`@multisoul/language`（AsyncStorage）
- `setLanguage` 同时调用 `i18n.changeLanguage(lang)` 使 UI 立即更新

### 3.5 Provider 注入

在 `mobile/app/_layout.tsx` 根 layout 中：
1. 应用启动时读取 `languageStore`，初始化 i18next
2. 用 `<I18nextProvider i18n={i18n}>` 包裹整个 app

### 3.6 翻译 key 命名规范

- 扁平结构，按模块前缀：`settings.title`、`agents.emptyState`
- 通用词汇不加前缀：`common.cancel`、`common.retry`、`common.loading`

## 4. Settings 页面 UI 变更

在 Settings 页面 **Preferences** section 新增 **Language** 行（位于现有三个 toggle 行之后）：

```
[Globe icon]  Language
              English / 简体中文        [当前语言] >
```

点击后弹出 ActionSheet 或 Bottom Sheet，选项：
- English
- 简体中文

选中后立即切换，Sheet 关闭。

**约束**：
- 图标使用 Lucide `Globe`（已有依赖）
- 颜色使用 `brandColors.cyan`（与 Ask before tool write 图标区分）
- 不破坏现有 Settings 页面布局和样式系统

## 5. 验收标准

### AC-1 语言文件完整性
- `en.json` 和 `zh.json` 包含所有覆盖范围内的 key，无遗漏
- CI 中运行 key 一致性检查脚本（可选，后续机械化）

### AC-2 默认语言逻辑
- 全新安装 + 设备语言为中文 → 显示简体中文
- 全新安装 + 设备语言为英文 → 显示英文
- 用户手动切换后重启 app → 保持上次选择

### AC-3 立即生效
- 在 Settings 页面切换语言 → 所有已打开的页面字符串**立即**更新，无需导航刷新

### AC-4 翻译覆盖率
- Tab Bar 标签（5 个）全部翻译
- Settings 所有 section 标签、行标题、副标题翻译
- Agents 空状态、列表标题、操作按钮翻译
- Activity 空状态、状态标签（Running / Completed / Failed）翻译
- Specs 列表标题、操作按钮翻译
- Workflows 标题、空状态翻译
- QR 扫码弹窗所有文字翻译（Scan / Manual tab、提示文字、错误信息）

### AC-5 动态内容不受影响
- Agent 名称、spec 标题、conversation 消息内容保持原样（不被翻译 key 替换）

### AC-6 类型安全
- i18next 使用 TypeScript 类型定义，`useTranslation` 的 key 有自动补全和类型检查
- `pnpm typecheck` 通过

### AC-7 测试
- `languageStore` 单元测试：持久化读写、`setLanguage` 触发 `i18n.changeLanguage`
- Settings 页面 language 行的快照 / 渲染测试
- 现有测试不回归（`pnpm test --watchAll=false` 通过）

## 6. 风险与约束

| 风险 | 缓解 |
|------|------|
| 已有测试 hardcode 英文字符串断言 | 更新测试使用翻译 key 或 mock i18n |
| 翻译 key 漏掉某些组件 | 全局搜索 hardcoded 字符串（`grep` + 人工审核）|
| AsyncStorage 读取异步导致 flash | 在 SplashScreen 持有期间完成语言初始化，避免语言闪烁 |
| 单文件 ≤ 500 行约束 | 翻译文件是 JSON，不受约束；i18n/index.ts 轻量 |
